# PSForge Desktop 2.0 Vision

## Summary

PSForge Desktop 2.0 will refine the app into a more cohesive PowerShell automation workbench. The focus is on improving the experience around the existing product strengths: script building, validation, AI help, guided workflows, desktop execution, Git support, and reusable automation assets.

## Goals

- Make the app feel like one integrated workspace instead of several adjacent feature tabs.
- Help users understand script risk, readiness, parameters, modules, and run impact before execution.
- Make common admin workflows faster to start through curated templates, command packs, and guided entry points.
- Make AI assistance contextual and practical rather than isolated in a separate surface.
- Improve visual polish while preserving the professional utility-tool identity.
- Strengthen desktop-native behaviors such as recent files, recovery, updates, local run history, transcripts, and command palette actions.

## Non-Goals

- Full rewrite of the app.
- Decorative redesign that reduces information density.
- Landing-page-style product visuals inside the desktop workspace.
- Replacing local/manual script building with AI-only workflows.
- Breaking existing 1.x script files, account flows, or Pro licensing assumptions without a migration path.

## Experience Principles

### Workbench First

The primary screen should feel like a working environment, not a marketing surface. Users should be able to open the app and immediately write, inspect, run, or refine PowerShell scripts.

### Safety Is Visible

Risk, validation, elevation, destructive operations, transcript capture, modules, parameters, and environment context should be visible before a script runs.

### AI Where Work Happens

AI should appear as actions near the script, selection, validation issue, run failure, or workflow state. The AI tab can remain, but the best AI interactions should be contextual.

### Curated, Not Crowded

Command and workflow libraries should feel curated. Search, categories, platform packs, favorites, risk indicators, and compact detail views should help users find the right automation path quickly.

### Desktop-Native Confidence

The Windows app should feel trustworthy: strong file handling, recovery, update clarity, recent files, run history, transcripts, local paths, and clear account/license state.

## Ideal User Impression

After opening PSForge Desktop 2.0, a Windows admin should think:

> This feels like the place where I can safely create, review, run, and reuse PowerShell automation.
